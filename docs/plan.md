# DART-QoE 구현 계획

## 1. 현재 상태 점검

- 목표: 기존 기능과 사용자 변경을 보존하면서 개선 범위를 확정한다.
- 변경 대상: 저장소 전체, 현재 실행파일과 화면
- 확인 방법: Git 상태, 테스트, 현재 화면 캡처, 주요 코드 흐름 확인

## 2. 제품 문서 정리

- 목표: 실제 구현과 검증 기준을 문서로 고정한다.
- 변경 대상: `docs/spec.md`, `docs/plan.md`, `docs/todo.md`, `docs/design.md`
- 선행 조건: 현재 기능과 화면 파악
- 확인 방법: 문서 간 기능·용어·완료 기준 일치 여부 검토

## 3. 입력 화면 개선

- 목표: 중요한 입력과 실행 행동을 먼저 보이게 하고 오류 수정 위치를 명확하게 한다.
- 변경 대상: `app.py`
- 작업:
  - 필드 라벨과 도움말의 위계 정리
  - 인라인 입력 오류 표시
  - 실행 버튼 문구 구체화
  - 로고·서명 영역 축소
  - 키보드 실행과 포커스 보강
- 확인 방법: 누락 입력, 잘못된 기간, 정상 입력 흐름 테스트

## 4. 결과 화면과 상태 개선

- 목표: 준비·분석 중·완료·오류 상태에서 다음 행동을 예측할 수 있게 한다.
- 변경 대상: `app.py`, `test_app.py`
- 작업:
  - 초기 빈 화면을 단계 안내로 변경
  - 결과 파일 버튼 문구와 활성 상태 정리
  - 오류 발생 시 문제와 해결 방법을 결과 영역에 표시
  - 분석 중 단계와 진행률 유지
- 확인 방법: 상태별 텍스트와 버튼 상태 테스트

## 5. 반응형 데스크톱 레이아웃

- 목표: 좁은 창에서도 글자 잘림과 의도하지 않은 가로 압축을 막는다.
- 변경 대상: `app.py`
- 작업:
  - 넓은 창은 좌우 2단
  - 좁은 창은 입력 → 결과 순서의 세로 배치
  - 최소 크기와 카드 여백 조정
- 확인 방법: 넓은 창과 최소 폭에서 화면 캡처 비교

## 6. 회귀 검증과 Excel 확인

- 목표: UI 변경이 분석과 Excel 생성을 깨뜨리지 않았는지 확인한다.
- 변경 대상: 테스트, 생성된 검증 Excel
- 선행 조건: UI 구현 완료
- 확인 방법: 단위 테스트, smoke test, Excel 핵심 수식·오류 검사, 전체 시트 렌더링

## 7. 배포와 인계

- 목표: 검증된 실행파일과 소스를 GitHub에 일관되게 배포한다.
- 변경 대상: 버전 정보, README, `docs/handoff.md`, Git 커밋, GitHub Release
- 확인 방법: 실행파일 해시, 재실행 확인, 깨끗한 Git 상태, 릴리스 자산 확인
