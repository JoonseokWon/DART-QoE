# DART-QoE 인계 기록

- 기준일: 2026-10-29
- UI·UX 적용 여부: 적용 / 화면 있음
- 목적: 공시 재무제표·주석을 이용한 이익 지속성, 현금전환, 운전자본과 순차입금 검토 보조
- 현재 상태: v0.3.0 화면 개선과 회귀 검증 완료. 배포 빌드·릴리스 결과는 아래에 갱신한다.

## 완료한 작업

- 제품 명세, 구현 계획, 화면 설계, 체크리스트 작성
- 좌우 카드와 좁은 창의 세로 배치, 전체 세로 스크롤 구현
- 입력 오류를 카드 안에 표시하고 입력값 유지
- 실행·결과 파일 버튼 문구, 빈 상태와 오류 복구 안내 개선
- 과도한 서명 영역 축소, 결과 요약 스크롤바 추가
- Windows 네이티브 한글 입력의 Tab·Shift+Tab·Enter와 포커스 표시 연결
- 기존 작업 폴더의 분석·Excel·테스트 변경을 보존해 통합

## 주요 결정과 이유

- 기존 남색·파란색 브랜드와 Tk 데스크톱 구조를 유지해 배포 부담을 줄였다.
- 좁은 창에서는 입력 후 결과라는 읽기 순서를 유지하고 스크롤로 높이를 확보했다.
- 한글 IME 안정성을 위해 네이티브 EDIT 컨트롤을 유지했다. 키 처리만 Tk와 연결했다.
- 네이티브 메시지 콜백 안에서 Tk를 직접 호출하면 창 활성화가 멈추는 접근이 있었다. 콜백은 이벤트만 저장하고 Tk의 주기 작업이 처리하도록 고쳤다.

## 실제 검증 결과

- Python 테스트: 30개 통과
- 숨김 UI 검사: 2100×1250 넓은 배치, 1300×980 좁은 배치. 준비·오류·성공·진행 상태와 네이티브 키 이벤트 통과
- DPI 150% 환경에서 네이티브 한글 입력과 넓은 화면, 좁은 오류 화면을 직접 확인
- Excel: 보고 영업이익 176.4억 원 + 손실 8.5억 원 - 이익 21억 원 = 정상화 영업이익 163.9억 원
- 전체 조정 '아니요' 변경 시 176.4억 원으로 복원 확인
- 핵심 수식 오류 검색 결과 0건, 9개 시트 렌더링 생성
- 차트 캐시가 비어 저장된 그래프가 렌더링에서 사라지는 문제를 확인했다. 원천 셀의 캐시 값으로 계열 캐시를 채워 선과 양쪽 축이 표시되는 것을 확인했다. ZIP 항목을 그대로 재사용하면 헤더 위치가 변하는 오류는 복사본을 기록하도록 수정했다.
- 개발 Python의 Tcl 읽기 실패는 샌드박스 밖에서 동일 코드가 통과해 실행 제한에 따른 것으로 확인. 번들 파일을 임의 수정하지 않았다.

## 미확인 사항과 남은 작업

- 실제 인증키로 신규 기업을 조회하는 네트워크 통합 테스트는 수행하지 않았다.
- 다중 모니터 간 DPI 변경과 실제 IME 조합 중 장문 입력은 추가 수동 검증 대상이다.
- Excel 자체에서 저장·재열기한 후의 차트 재계산 검사는 이번 작업에 포함하지 않았다. Artifact Tool에서 수식 재계산·선택 변경·렌더링을 확인했다.
- 업종별 계정 매핑, EBITDA 추출, 최근 분석 기록은 후속 기능이다.

## 관련 파일과 실행

- `app.py`: 화면, 키 저장, 결과 요약과 Excel 실행
- `qoe.py`: DART 조회·계정 매핑·후보 탐색
- `export_workbook.mjs`: Excel 생성
- `scripts/verify_ui.py`: 인증키·네트워크 없이 UI 상태 검사
- `scripts/verify_workbook.mjs`: Excel 수식·재계산·렌더링 검사
- `scripts/build_exe.ps1`: Windows 단일 실행파일 빌드
- `scripts/publish_release.py`: 기존 Git 인증을 이용한 릴리스 배포. 비밀값은 출력하지 않음

사용자는 `DART-QoE.exe`를 실행한다. 개발자는 번들 Python으로 `-m unittest discover -v`를 실행한다. 소스 UI 실행에는 해당 Python의 Tcl/Tk 경로가 필요하다.
