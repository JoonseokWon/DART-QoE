# DART-QoE 화면 설계

## 설계 목표

한 화면에서 분석 조건을 입력하고 진행 상태와 결과를 확인한다. 자동 결론보다 원문 확인과 Excel 검토로 이어지는 행동을 분명히 안내한다.

## 주요 화면과 사용자 흐름

### 분석 화면

1. 상단: 제품명과 한 줄 설명
2. 분석 조건 카드: 인증키, 회사, 기간, 리스부채 선택, 실행 버튼
3. 검토 결과 카드: 상태, 분석 범위, 요약, 결과 파일 행동

넓은 창에서는 분석 조건과 결과를 좌우로 배치한다. 좁은 창에서는 분석 조건이 먼저, 검토 결과가 다음에 오도록 세로로 배치한다. 입력 → 실행 → 결과 확인이라는 실제 작업 순서를 그대로 따른다.

## 레이아웃 선택 이유

- 분석 조건은 한 번에 훑을 수 있는 단일 카드로 유지한다.
- 결과 영역은 상태, 검토 범위, 요약, 파일 행동을 위에서 아래로 배치한다.
- 제품 서명과 로고는 기능보다 우선하지 않도록 작은 푸터로 축소한다.
- 결과의 핵심 검토 범위는 같은 크기의 작은 카드로 묶어 벤토형 요약 역할을 하게 한다.

## 공통 시각 규칙

- 배경: 밝은 회청색
- 주요 카드: 흰색, 얇은 경계선, 충분한 내부 여백
- 대표 강조색: 파란색. 실행 행동과 진행률에 사용
- 성공: 초록색, 오류: 빨간색, 확인 필요: 연한 노란색
- 제목은 진한 남색, 본문은 짙은 회색, 설명은 중간 회색
- 필드 라벨은 왼쪽 정렬하고 바로 아래에 입력을 배치한다.
- 버튼 문구는 결과가 명확한 동사형으로 작성한다.

## 상태별 동작

### 준비

- 세 단계 사용 흐름과 Excel에 포함되는 내용을 보여준다.
- 결과 파일 버튼은 비활성화한다.

### 입력 오류

- 입력값을 유지한다.
- 분석 조건 카드 안에서 문제와 해결 방법을 표시한다.
- 가능한 경우 첫 오류 필드로 포커스를 이동한다.

### 분석 중

- 실행 버튼을 비활성화한다.
- 실제 진행률과 현재 수집·계산 단계를 표시한다.
- 결과 영역에 분석이 진행 중임을 안내한다.

### 완료

- 핵심 지표와 추가 확인 포인트를 표시한다.
- `Excel 검토 파일 열기`와 `저장 폴더 열기`를 제공한다.

### 오류

- 문제 요약과 사용자가 확인할 항목을 결과 영역에 표시한다.
- 입력값을 유지하고 실행 버튼을 다시 활성화한다.
- 상세 오류는 로그 파일에 남긴다.

## 접근성과 반응형 기준

- 모든 입력에는 화면에 보이는 라벨이 있다.
- 기본 Tab 순서는 인증키 → 저장 여부 → 회사 → 기간 → 리스부채 → 실행 순서다.
- Enter로 분석을 실행할 수 있다.
- 버튼과 입력의 포커스 표시를 유지한다.
- 최소 폭에서 좌우 패널을 세로로 전환한다.
- 세로 공간이 부족하면 전체 화면에 스크롤바를 제공하고 결과 요약에도 별도 스크롤바를 제공한다.
- Windows 네이티브 한글 입력칸의 Tab·Shift+Tab·Enter를 Tk 키보드 순서와 연결한다. IME 조합 중 Enter는 입력기에 전달한다.
- 텍스트는 줄바꿈하되 중요한 버튼과 입력은 잘리지 않게 한다.

## 화면 검증 방법

1. 1440×900 내외의 넓은 창에서 좌우 2단과 정렬 확인
2. 최소 폭에서 세로 배치, 글자 잘림, 가로 스크롤 여부 확인
3. 필수 입력 누락과 잘못된 기간으로 인라인 오류 확인
4. 분석 중 진행률과 버튼 비활성 상태 확인
5. 완료 상태의 요약과 파일 열기 버튼 확인
6. 키보드 Tab 이동과 Enter 실행 확인
